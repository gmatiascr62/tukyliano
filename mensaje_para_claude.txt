REVISIÓN DE TUKYLIANO PARA CLAUDE

Objetivo: mejorar la app Android Flutter de práctica de italiano y mantener la IA local/offline después de descargar el modelo. No reintroducir Gemini, APIs ni servicios externos.

## Modelo y compatibilidad
- modelo.dart usa Qwen2.5-1.5B-Instruct Q4_K_M (~1,1 GB), mientras algunos workflows/documentos mencionan Qwen3-0.6B. Unificar la configuración y documentación con el modelo realmente utilizado.
- No cambiar a Qwen3-0.6B solo por ser pequeño: hubo problemas previos de latencia/razonamiento y repetición de entrada. Probar alternativas en teléfonos reales midiendo italiano, latencia, memoria, temperatura y estabilidad.
- La app está configurada para arm64-v8a y Android API 24+. El umbral de 4 GB RAM no garantiza que funcione bien en todos los teléfonos; el modelo requiere memoria adicional.
- Mantener descarga reanudable y validación SHA-256; verificar que un archivo incompleto nunca se acepte como válido. No eliminar INTERNET, porque hace falta para descargar el modelo y obtener actualizaciones.
- Revisar compatibilidad de llama.cpp/llama_cpp_dart y requisitos Android relevantes.

## Observación de una conversación real (23/10/2026)
Intercambio:
IA: «Ciao! Sono Tuky. Hai fratelli o sorelle?»
Usuario: «Ciao tuky, io sono Matías, io ho una sorella»
IA: «Ah, Matías! Sono felice di conoscerti. Come va la tua vita?»
Usuario: «Piacere tuky, la mia vita è bella, lavorando molto»
IA: «Ciao Matías! Sembra che tu abbia un impiego ben concreto. Cosa ne pensi della tua vita professionale?»

«Un impiego ben concreto» suena poco natural y formal para principiantes. La IA no responde de forma sencilla al comentario de que el usuario trabaja mucho y cambia el tema a la vida profesional. Alternativa natural: «Capisco! Lavori molto. Che lavoro fai?» («Entiendo. Trabajás mucho. ¿De qué trabajás?»).

Mejorar el prompt para que Tuky:
1. Sea un compañero amigable y natural, no un asistente formal.
2. Use italiano cotidiano, frases cortas y vocabulario inicial; aumentar la dificultad gradualmente.
3. Responda primero a lo que el usuario dijo y mantenga el contexto; evitar repetir «Ciao Matías!» en cada turno.
4. No derive automáticamente cualquier comentario al trabajo ni asuma profesión, situación o sentimientos.
5. Haga preguntas de seguimiento naturales, sin obligarse a terminar cada respuesta con una pregunta.
6. Corrija de forma breve y amable solo cuando sea útil, sin interrumpir cada turno.
7. Mantenga separadas conversación, traducción y revisión gramatical, sin contradicciones entre prompt y reglas locales.

No culpar al modelo por una sola captura. Primero probar el prompt mejorado con el mismo modelo y varios temas (familia, comida, pasatiempos, rutina diaria); después comparar modelos si hace falta.
